# SafeHer — UI/UX Master Plan

**Product:** a mobile-first web app for women's safety (SOS, live location, contacts, fake call, evidence, translator).
**Audience:** women in India, often stressed, one-handed, on a phone, sometimes offline. English + Hindi.
**Primary job:** make the SOS action instant, trustworthy and impossible to fumble — and keep everything else calm.

## Design direction
- **Mood:** calm, protective, modern. Not alarming until it needs to be.
- **Colour = meaning.** Coral `#FF4D5E` is for emergencies *only*. Lilac `#A596FF` = interactive. Teal `#2DD4A7` = safe / active.
- **Base:** Ink Plum `#120E24` background, surfaces `#1E1840 / #271F4F / #322960`. (Light theme arrives in Phase 5 — tokens are ready.)
- **Type:** Bricolage Grotesque (headings, 500–800) + Figtree (body). Devanagari falls back to Noto Sans Devanagari.
- **One memorable element:** the SOS button. Everything else stays quiet.
- **Rules:** sentence case, plain verbs, buttons say what happens ("Send alert", not "Submit"), errors say how to fix it, empty states invite action. Touch targets ≥ 48px. Body text ≥ 15px, inputs 16px (stops iOS zoom).

## Audit — what was found
1. `user-scalable=no` blocked pinch-zoom (accessibility failure). **Fixed in P1.**
2. `#offline-voice-setup` div was never closed, nesting the offline translator results inside a hidden box. **Fixed in P1.**
3. Tab bar at the top, emoji as icons (render differently on every phone), Bebas Neue uppercase look, decorative gradient blobs. **Fixed/replaced in P1** (emoji inside cards remain until P2).
4. Many inline `style=""` attributes and `onclick=""` handlers; two parallel styling layers (`style.css` + `theme.css`). **P6.**
5. SOS fires on a single tap (`triggerSOS()`). Check whether the JS already has an undo window; if not, add a 3-second cancel countdown. **P2.**
6. The Fast2SMS API key is typed into the browser (a client-side secret). Needs a small backend/proxy or a clear warning. **P5.**
7. The Home "Share location" card is dense (SMS + WhatsApp queue + per-contact buttons). Needs one simple flow. **P2.**
8. The Track tab stacks four long cards; Translate tab has two heavy modes. **P3, P4.**
*(The 2,287-line `script.js` was not fully audited yet — start P2 with a read-through of `triggerSOS`, tracker, recorder and storage code.)*

## Guardrails (never break these)
- Keep working: `switchTab()` (needs `.tab-btn[data-tab]` + `#tab-<name>` + `.hidden`), `triggerSOS()`, and every `id` used by `script.js`. Before renaming any `id` or class, `grep` for it in `script.js`.
- JS toggles visibility with the `.hidden` class (`display:none !important`) — keep it.
- No frameworks or build step; stays plain HTML/CSS/JS so it opens by double-click.

- `ui.js` loads after `script.js` and OVERRIDES `renderContacts`, `addContact`, `deleteContact`, `displayLocationOnScreen`, `updateTimerDisplay`, `endFakeCall`, `renderIncidents`, `showStatus` (strips emoji from every popup), `setTranslatorState`, `setListenButton`. Change those there, not in `script.js`. Settings keys in localStorage: `safeher_theme` (auto/dark/light), `safeher_vibrate`, `safeher_onboarded`. Both `requestSOS(true)` (practice mode) and the Home SOS button use the fixed 3-second cancel window before `triggerSOS()`. The SOS ringtone loops for 5 seconds.

- `window.i18n(key)` returns the Hindi text when the interface language is Hindi, else the key; use it for `confirm()` and for HTML built in JS outside the page (the report window). `window.setState(el, kind, text, retryFn)` is the one way to show loading/error text inside a card. The status toast must stay `position:fixed`, so it never moves the SOS button.

- Language names in the translator selects are translated in Hindi mode for display only: `script.js` must read the option `value` / `code`, never the option text.

- First-run language: `obLang(v)` (switch in every first-run step) and the one-time Hindi default for fresh installs live in the first-run block of `ui.js`. `PAT` replacements in the language block can be functions (used for incident dates).
